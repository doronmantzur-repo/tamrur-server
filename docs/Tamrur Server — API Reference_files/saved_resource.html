API Reference

Mass-casualty-incident coordination backend. An event is the incident; injuries and evacuations are logged against it, and injuries-evac is the many-to-many join recording which evacuation(s) each casualty used. Injuries treatment and vitals hold one record per event each — a running note and a snapshot of readings, not a history log.

Authentication

Every route below except /auth/register and /auth/login requires Authorization: Bearer <token>. Tokens are issued by login/register, are signed HS256, and expire after 24h.

All errors share one shape from a central handler: { "error": true, "message": string, "statusCode": number } — shown per-endpoint below only where the status code or message is specific to that route.

Notes

  • Enum fields (type, status, urgency, method, evac-ability) are enforced by Postgres. An invalid value fails the insert/update and surfaces as a generic 500, not a 400, unless the controller validates it first (noted per field above where it does).
  • GeoJSON Points round-trip: send { "type": "Point", "coordinates": [lng, lat] }, get the same shape back (longitude first, per GeoJSON — not lat/lng).
  • Column names containing a hyphen ("event-id", "evac-abillity", "recommended-evac-dest", "evac-ready", "repiratory-rate") appear exactly that way in JSON responses.
  • Injuries Treatment and Vitals both use "event-id" as their primary key (no separate row id), so each event can have at most one record in either table. Update in place with PUT rather than creating a new one.
